## 细则

第 2 项已实现（2026-09-28）。评测与浏览器验收见[第 4 周评测](../codex/evidence/2026-09-28-week4-model.md)。

### 文档转换

- **入口**：`planning/retrieval/convert.py`。
  - 支持 .md、.txt、.pdf、.docx、.pptx、.xlsx、.xls、.html、.htm，单个文件不超过 20 MB。
  - 依赖锁定在 `requirements-docs.txt`。未安装时，PDF、Markdown、文本照常可用，其他格式提示安装。
- **PDF 不用 MarkItDown 自带的转换**：在 ITU 原文上，它把 94 页里的 40 页当成表格，打乱公式和表格，速度也慢 3–5 倍。
  - PDF 改用本项目的按页转换器：pypdf 取文本，每页加页码标记。
  - 这个转换器实现 MarkItDown 的转换器接口，入口仍然统一。
  - 这是实现时的自主决定，已告知用户。
- **缓存**：转换结果放 `knowledge/sources/converted/`（被忽略）。文件头记录原文与文本的 SHA-256，每次读取都核对。
- **切块**：
  - 每块不超过 800 字。PDF 按页切，Markdown 按标题切，幻灯片编号作为定位。
  - 只有标题、没有正文的节，并入下一节。
  - 表格跨块时重复表头。
  - 块数由 318 变为 314，其中 XX-300 手册 3 块。

### 资料页

- **添加文档**：
  - 原文存 `knowledge/sources/added/`（被忽略）；清单记录 SHA-256，标为不可再分发。
  - 同一文件不重复登记；转换失败时删除原文。
- **抽取**：
  - 用户选同一文档的 1–6 个片段，再选“设备 / 站点 / 公式”。
  - 模型按固定表单填写，每个字段附逐字原文引用。
  - 程序核对三项：
    1. 引用必须出现在所选片段里。
    2. 数值必须出现在引用里（“−”按负号处理）。
    3. 名称必须出现在引用里。
  - 公式另按原文算例复算，容差为原文小数位的一半。
  - 核对不通过时重试一次，缺引用的字段一次全部告诉模型。
- **草稿**：
  - 每个字段显示值、原文和核对结果；表格行的引文上方显示表头。
  - 库里已有同名或同编号的记录时，草稿不可入库。
- **审核**：
  - 审核人必填。通过时写入 `knowledge/facts/devices.json`、`sites.json` 或 `knowledge/formulas.json`：只追加一条，不改其他记录的格式。驳回必须写原因。
  - 审核用线程锁加 SQLite `BEGIN IMMEDIATE` 串行执行；中途崩溃时，按已写入的记录恢复。
  - 审核会改变知识库。审核前生成、尚未确认的计划不能再确认（“知识目录已变化”），需要重新提交。
- **公式卡**：入库后先用作资料与检索；计算规划仍只用已支持的五张卡。

### 追问（换电台、换站点）

- **规则先判**。以下情况反问，任务不变：
  - 说法犹豫。
  - 库里没有，或只有未审核的草稿。
  - 已经在用。
  - 没说换哪一端。
- **模型再读**：规则判为明确换用时，模型独立读一遍，填三项：换上的电台、被换下的一端、接替的站。
  - 与规则一致才合并。
  - 模型照抄当前电台或同一站点，按“没换”处理。
  - 不一致时反问，并在对话里写出模型的读法。
- **合并**：
  - 在任务文本原位置替换名称，产生新版本，需要重新确认。
  - 关于同一电台或站点的新问题，替换旧问题。
- 其他补充（数值、单位等）仍走原来的补充合并。

### 版本对比

- 结果下方一行，例如“上一版（XX-100）链路余量 5.93 dB，不满足 → 本版（XX-200）20.93 dB，满足”。
- 只和最近一次换用之前、同一输入的结果对比。那一版没算出结果（如超出视距）时不显示。
