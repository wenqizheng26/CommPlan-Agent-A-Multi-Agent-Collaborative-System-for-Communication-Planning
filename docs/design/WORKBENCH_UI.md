## 计划卡（第 3 周“计划确认页 / 逐步结果页”的骨架）

- 目标、条件各一行；每步一行：序号、名称、出处、输出；展开后每个输入带来源标签（原文 / 手工 / 上一步 / 待补充 / 冲突）。
- 待确认、待补充时步骤展开；已完成时收起，行内显示结果。
- 模型假设默认收起并写明条数；结果页“适用范围”只露第一条。
- 公式页逐步显示每一步的登记公式：最后一步的卡片随任务保存；其余由只读接口 `/api/formula-cards` 读取，内容哈希与任务证据一致才显示，否则标“公式卡已变更”。
- 第 3 周接入：站点库、设备库（标“模拟”）、假设值、计划来源、反求曲线。

## 文案

短标签，专业词保留（出处、校验项数、Agent 名只在流程图），不写长段说明；只写代码真实做的事。示例：“缺 7 项参数”“3 步计算链 · 待确认”“完成 · 9/9 校验通过”“规则接管 · 数值不变”。英文参数名显示时一律换成中文。

## M1 第 3 周：模型答复、查库来源与反求（用户 2026-09-25 确认）

后端字段已实现，见 [A2/A3 记录](../codex/evidence/2026-09-25-A2-A3-review.md)；页面由 Codex 任务 C14 实现。

### 结果区（从上到下）

1. **请核对提示条**：审查结论为“请核对”（`final_report.review.decision == 'caution'`）时，在答复上方显示黄色提示条“审查提示需要核对”，其下逐条列出审查意见。
2. **答复卡**：标题行“答复 · 结论标签”（通过 / 请核对）；正文是模型写的答复（`final_report.answer.text`）。答复被隐藏（`answer.withheld`）时，正文位置写“说明未通过数字核对，只显示逐步数值”。没有模型答复（规则接管或确定性模式）时不显示答复卡，程序结论按现在的样式放在主位。
3. **程序结论**：答复卡下方一行灰色小字“程序结论：……”（`final_report.conclusion`）。
4. **余量要求**：有 `final_report.requirement` 时，在主数值旁写“要求 ≥ 10 dB · 满足 / 不满足”。
5. **反求**：有 `final_report.solve` 时单列一块。写明所需发射功率（至少 / 至多）、两侧复核（左、右两点的发射功率与余量，以及是否满足）、迭代次数与残差；`rated.exceeded` 为真时加红色提示“超过所选电台的额定发射功率 37 dBm”。下面画余量随发射功率变化的曲线：用 `solve.samples` 的 17 个点，标出要求线和解。反求出错（有 `error`）时写“反求没有结果：原因”。
6. **审查意见**：“通过”时若有意见，放在程序结论下方；每条前面标类别（风险 / 假设 / 建议）。被隐藏的意见写“该条未通过数字核对”。
7. **逐步数值**：每一步下方显示模型写的说明（`final_report.explanation`，按 `id` 对应步骤）；被隐藏的说明不显示。

### 视距外停止

`status == 'NEEDS_MODEL'` 且 `failure.code == 'BEYOND_LINE_OF_SIGHT'` 时，结果区写“超出视距，未计算”，列出直线距离与视距（`failure.details` 中的 `distance_km`、`radio_horizon_km`）和 `failure.next_action`；逐步列表中已算的两步（直线距离、视距）照常显示，之后各步写“未计算”。

### 计划卡

按计算书的顺序排：标题 → 目标与条件 → 适用性评估 → 步骤 → 本次假设（2026-09-26 定，设计见 [AGENT_LED](AGENT_LED.md) §2a）。

```
计划 · 专业计算 Agent 编写 · 程序校验通过
目标  链路余量 ≥ 10 dB；不满足时求最小发射功率
条件  自由空间基准

适用性评估 · 可以确认
  对题    计划回答能否留足 10 dB 余量，不满足时反求发射功率。
  适用性  A站在海岸、B站在海岛，路径跨海面；自由空间只作基准，未计海面反射与多径。
  假设    两端馈线损耗按假设取 2 dB，实际取决于馈线长度。

1 直线距离   出处   → 输出
  由两站经纬度与高程算两天线间直线距离
2 视距       出处   → 输出
  先确认在视距内，自由空间模型才成立
  视距检查：直线距离不超过视距，否则停止
3 路径损耗 …（每步一行，下面一行灰字理由）

本次假设 4 条（可直接改）
```

- **标题**：追问阶段（`AWAITING_INPUT`）写“计划预览 · 程序拼链”；`calculation_plan_proposal.origin == 'model'` 写“计划 · 专业计算 Agent 编写 · 程序校验通过”；`origin == 'program'` 写“计划 · 程序拼链”，有 `origin_note` 时在括号里附上（如“模型计划未通过校验：缺视距一步”）。
- **目标行**：有 `requirement` 时写“链路余量 ≥ 10 dB”；有 `solve_if_unmet` 时加“不满足时求最小发射功率”。条件行照旧。
- **适用性评估**（`calculation_plan_proposal.assessment`）：标题“适用性评估 · ”加 `label`（“可以确认”绿色 /“建议核对”黄色）；下面逐条列 `notes`，每条前面标类别（`label`：对题 / 适用性 / 假设），默认展开。被隐藏的条目（`withheld`）写“该条未通过数字核对”。`mode == 'skipped'` 时只写一行灰字“未做模型适用性评估”；没有 `assessment`（追问阶段）时不显示这一块。只作提示，确认条不变。
- **步骤**：每步一行“序号、名称、出处、输出”，下面一行灰字写 `steps[].why`（模型的理由）；程序拼链的步骤没有这一行。展开后每个输入带来源标签。
- **视距检查**：有 `checks` 时，在直线距离、视距两步之后加一行“视距检查：直线距离不超过视距，否则停止”。
- **来源标签**：原文 / 手填 / 站点库 / 设备库 / 假设 / 上一步 / 待补充 / 冲突。来源 `kind` 为 `site`、`device` 且记录是模拟数据时，标签后加“模拟”（记录由新的只读接口 `/api/facts` 提供）。已识别列表用同样的标签。
- **本次假设**：`calculation_plan_proposal.assumed` 放在步骤之后，标题“本次假设 N 条（可直接改）”，默认展开；公式卡注释仍在折叠的“模型假设”里。
- **假设值可以直接改**（只限标“假设”的值）：值旁边有输入框，单位固定为该参数的单位。按回车或点“保存”就提交：原文不变，表单参数（`manual_parameters`）加上这一项，走原有的“编辑”命令，系统重新整理计划（本机模型约 20–28 秒，含写计划与适用性评估），然后需要重新确认。改过的值标“手填”，并注明原来的假设值，例如“手填 3 dB（原假设 2 dB）”；原假设值取自公式卡参数的 `default`（`/api/formula-cards`）。
