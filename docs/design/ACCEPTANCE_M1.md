# 一个月验收点（M1）

状态：用户 2026-09-24 确认。演示或验收节点：2026-10-24 前。
定位：本机离线的通信筹划助手，同时作为单位内部工具与科研原型。按“先打地基再扩用途”推进：通用计算引擎 → 公式入库管道 → 选型 → 组网与覆盖。M1 只覆盖前两项的一部分。
相关规格：[CALCULATION_PLANS](CALCULATION_PLANS.md)、[KNOWLEDGE_FACTS](KNOWLEDGE_FACTS.md)。

## 演示问题

> A 站到 B 站用 XX-100 电台、2 GHz，要留 10 dB 余量，能通吗？不能的话发射功率至少要多大？

| 能力 | 期望行为 |
| --- | --- |
| 听懂 | 在模拟站点库里识别 A、B，取出坐标和天线高度；在模拟设备库里识别 XX-100，取出发射功率、天线增益、接收灵敏度；没人提的量（如馈线损耗）列为假设 |
| 拆解 | 计划为：用坐标算直线距离 → 视距检查 → FSPL → 接收功率 → 余量 → 余量不足时反求最小发射功率；程序检查计划，用户确认一次 |
| 讲清楚 | 回答“余量 x dB，不满足 10 dB；发射功率至少 y dBm”；每一步都能展开，每个输入都标明来源（原文 / 站点库 / 设备库 / 假设 / 上一步） |

站点和设备数据是模拟的，标注 `simulated: true`，页面上显示“模拟数据”。以后换成真实数据时只换数据文件，不改程序。设备库沿用 KNOWLEDGE_FACTS 的事实机制，新增 `device` 类型。

## 三档验收

| 档次 | 内容 | 通过标准 |
| --- | --- | --- |
| 保底 | v0.1.0 发布门禁通过；通用引擎能算出参数全部写在原文里的链路余量；页面展示计划并确认计划 | 余量与手算差 ≤ 0.01 dB；现有 FSPL 任务结果与 v0.1.0 逐位一致 |
| 目标 | 演示问题完整跑通：站点库与设备库补全、视距检查、反求、模型写计划（出错或离线时改用程序拼链） | 主场景加下列 5 个变体全部通过；反求与闭式解的相对误差 ≤ 1e-6；模型离线时数值与在线相同 |
| 加分 | 从一份公开 ITU-R 文档抽取一张公式草稿，审核后入库并参与计算；记录模型计划与程序拼链的一致率 | 草稿未审核前不能参与计算；评测结果落到文件 |

目标档变体：
1. 缺少天线高度时追问高度。
2. 两站超出视距时拦下，不给损耗值。
3. 用户给出的发射功率与设备库不一致时提问。
4. 同名站点存在歧义时让用户选择。
5. 余量本来就够时直接回答“能通”，不做反求。
