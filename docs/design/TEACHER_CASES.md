## 三条案例

| 案例 | 用户输入 | 期望 |
| --- | --- | --- |
| 一：完整输入 | 算一下 A 楼顶到 B 楼顶的无线链路余量。距离 10 公里，频率 5.8GHz，发射功率 20dBm，发射天线增益 18dBi，接收天线增益 18dBi，调制方式 QPSK。 | FSPL ≈ 127.71 dB，Prx ≈ −71.71 dBm，灵敏度 −100 dBm，余量 ≈ 28.29 dB，满足 |
| 二：缺项 | 从石家庄山顶基站连到乡镇，想用 5.8G，传视频，要稳定，功率和天线还没定。 | 识别站点 A、B，5.8 GHz，业务为视频。列出缺失项：距离、发射功率、发射增益、接收增益、调制方式。给出默认值并标“默认补全，需确认”：10 km、20 dBm、18 dBi、18 dBi、QPSK。用户采用后计算，数值同案例一 |
| 三：调制对比 | A 到 B 距离 8 公里，频率 2.4GHz，发射功率 17dBm，发射天线 12dBi，接收天线 12dBi，分别用 QPSK 和 16QAM 算余量，哪个更稳？ | FSPL ≈ 118.11 dB，Prx ≈ −77.11 dBm。QPSK 余量 ≈ 22.89 dB，16QAM ≈ 17.89 dB，相差 5 dB，推荐 QPSK。模型解释：调制阶数越高，灵敏度越差，余量越小 |

老师要的报告内容：

- 原始输入、解析字段、缺失项与补全；
- 工具调用参数；
- FSPL、Prx、灵敏度、余量、是否满足；
- 对比表（案例三）；
- 模型解释。

## 决定

| 项 | 决定 |
| --- | --- |
| 公式 | 链路余量用老师的式子：FSPL = 32.44 + 20lg d(km) + 20lg f(MHz)，Prx = Ptx + Gtx + Grx − FSPL，余量 = Prx − 灵敏度。单独算 FSPL 时仍用 `fspl_ghz`（92.4 常数），保持与 v0.1.0 逐位一致 |
| 调制灵敏度 | QPSK −100、16QAM −95、64QAM −90 dBm。放在 `knowledge/facts/modulations.json`，页面标“模拟参数，可配置” |
| 范围 | 只算自由空间链路余量。馈线损耗和其他损耗按 0 计，记为假设，不追问。用户没写“自由空间”也不追问条件 |
| 统一工具 | 在工具注册表登记 `calc_link_margin`，输入输出用 JSON Schema 约束。它内部依次调用三张登记卡：`fspl_mhz` → `received_power` → `link_margin`，每步结果都保留 |
| 缺项补全 | 先列出缺失项。默认值来自可配置的典型值表（`knowledge/facts/typical_values.json`），模型从中挑选并说明理由，例如“要稳定”选 QPSK。表单里预先填好，标“默认补全，需确认”；用户可以一键采用，也可以修改 |
| 站名 | 用户给了距离，就以距离为准，站名只作标签（如“A 楼顶”不去匹配库里的 A 站）。用户没给距离，才查站点库 |
| 多种调制 | 一次需求可以列多种调制，共用 FSPL 和 Prx，每种调制各算一个余量。输出对比表、余量差值，推荐余量最大的一种 |
| 解释 | 审查 Agent 要解释结论为什么成立，不只说怎么算。数字只能引用工具结果（沿用 H4） |
| 中间结果 | 每算完一步，对话区追加一张“工具计算”卡片，写明工具名、参数和结果。流程图不变，只亮当前节点 |
| 报告 | 结果页加“报告”视图，按上面的字段排版，可打印或存成 PDF |
| 日志 | 页面分“模型调用”和“工具计算”两块，只显示概要；完整的 prompt 与 response 存日志文件。一次只加载一个模型，统一记录模型名 |
| Agent 名称 | 流程图上加英文名：总控 = Coordinator，需求 = Requirement，计划与计算 = LinkBudget，审查与解释 = Report |
| 不改 | 技术栈（LangGraph、自建服务、llama.cpp，本机离线）；状态名（未启用、运行中、成功、失败，与老师的四种一一对应）；页面不展开 prompt 全文 |
