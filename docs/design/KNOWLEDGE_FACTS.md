# 知识库事实参数：设计规格

状态：构思定稿，未实施。排在 v0.1.0-demo 发布之后，作为下一阶段第一个功能。
决策来源：用户 2026-09-24 确认——两地距离与站点坐标两种事实都支持，以坐标为主；距离指站点间直线距离，并做视距检查；发布之后再做。

## 1. 要解决的问题

用户说“从 A 站到 B 站，频率 2 GHz，求路径损耗”。现在参数只有两个来源（原文、手工填写），这句话会被判为缺少距离并追问。目标是：当知识库里有 A、B 的资料时，由程序给出可追溯、需用户确认的距离。

## 2. 不变量（沿用现有原则）

1. 数值不由模型给出。模型最多识别原文中的地点提及，且必须逐字引用原文。
2. 知识库给出的参数是**第三种来源**，与原文、手工值同等要求：带出处、进入确认快照、由用户确认后才计算。
3. 与用户给出的值冲突时，按现有冲突机制提问，由用户裁决；不自动覆盖任何一方。
4. 由坐标得出的距离由登记公式计算，程序可独立复核；知识库更新后，已确认任务按现有“知识目录已变化”规则处理。

## 3. 事实记录（结构化，入库时审核，运行时不从正文现场抽取数字）

```json
{"id": "site:a-coastal-01", "type": "site", "names": ["A 站", "A 市岸站"],
 "position": {"lat": 30.1234, "lon": 121.5678, "datum": "WGS84", "height_m": 45, "height_ref": "ground"},
 "source": {"title": "…站址表", "version": "2026-06", "locator": "表 3 第 12 行"}}

{"id": "link:a-b-survey", "type": "link_distance", "from": "site:a-coastal-01", "to": "site:b-island-02",
 "value": 42.30, "unit": "km", "meaning": "slant_range", "method": "实测",
 "source": {"title": "…勘测报告", "version": "v2", "locator": "第 3 页"}}
```

- `meaning` 只接受 `slant_range`（两天线间直线距离）；地表距离、公路里程不能作为自由空间公式的 d。
- 原始资料是正文时，由 RAG 负责人在入库时抽取为上述记录并保留原文定位；抽取结果须人工或规则审核后入库。

## 4. 得出距离的两条路径

| 路径 | 条件 | 数值来源 |
| --- | --- | --- |
| 实测链路距离 | 存在 `link_distance`，两端站点都匹配，`meaning = slant_range` | 直接使用记录值 |
| 坐标计算（主路径） | 两端站点都有坐标与高度 | 登记公式卡 `slant_range_wgs84`：WGS84 经纬高 → 地心坐标 → 两点弦长 |

同时存在两者且相差超过 1% 时，作为冲突提问，不自行取舍。

## 5. 视距检查

- 登记公式卡 `radio_horizon`：d_h ≈ 4.12 × (√h₁ + √h₂) km（h 为天线离地高度，单位 m，等效地球半径系数 k = 4/3）。
- 直线距离大于视距时，按现有“超出适用范围”（NEEDS_MODEL）拦下，说明“两站超出视距，自由空间假设不成立”，不给损耗值。
- 缺少天线高度时，追问高度；不猜默认值。
- 菲涅耳区余隙、地形遮挡属于后续传播模型范围，不在本功能内。

## 6. 流程接入

1. 规则解析发现“距离”缺失，且原文中有两处以上地点提及（由规则或模型识别，均需逐字原文证据）。
2. 调用事实检索：先把提及解析为站点实体，再查链路距离或坐标。
3. 程序核验：名称精确或别名匹配、类型正确、单位与量纲正确、记录唯一；有歧义（同名站点、多个版本）时，用现有“需求确认与补充”面板列出候选让用户选择。
4. 生成参数草稿：`origins` 增加 `kind = "knowledge"`，记录实体 id、事实 id、来源定位、计算方式（实测 / 坐标计算）与中间值（两端坐标、高度、视距）。
5. 用户在参数页核对并确认；确认快照包含上述事实与知识库版本。
6. 专业计算与现在相同。

需要改动的冻结合同：报告中参数来源的 `kind` 增加 `knowledge`，`requirement_validation` 增加对知识来源的复核（事实存在于快照、坐标计算可重算）。这是本功能放在发布之后的原因之一。

## 7. RAG 接口增补（给 RAG 负责人）

```python
class FactService(Protocol):
    def resolve(self, mentions: list[str]) -> list[EntityMatch]: ...      # 提及 → 候选站点（含匹配方式：名称 / 别名）
    def facts(self, entity_ids: list[str], quantity: Literal['link_distance', 'position']) -> list[Fact]: ...
    def describe(self) -> dict: ...                                        # 记录数、版本
```

合同测试要点：只返回库中存在的记录；解析结果确定且可复现；不联网；不返回未审核记录；每条事实都有来源定位；单位与 `meaning` 字段取值受限。与现有 `RetrievalService`（公式卡与文档片段）分开，互不影响。

## 8. 页面

- 参数表的来源增加“知识库”：显示来源文档、版本、定位；坐标计算时可展开两端坐标、高度、直线距离与视距。
- 地点有歧义时在右侧提问面板列出候选。
- 「依据」页签增加“事实”分组；超出视距时在结果位置显示阻断原因。

## 9. 验收基准

- 数值基准：选取已知坐标的站点对，用独立来源（大地测量计算器或文献算例）核对弦长与视距，误差限在规格中写明。
- 流程用例：唯一匹配、同名歧义、缺高度、超出视距、实测与坐标冲突、用户给值与知识库冲突、知识库更新后的已确认任务。
