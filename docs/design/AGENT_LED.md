# 模型主导：在原框架上改造（M1 第 2–4 周）

状态：用户 2026-09-25 确认（第二版：在原框架上改，降低开发难度）。只作用于分支 `claude/calc-plans`，v0.1.0 候选不受影响。
取代：[KNOWLEDGE_FACTS](KNOWLEDGE_FACTS.md) §6 第 1 步（规则识别地点）；[MODEL_RETRIEVAL](MODEL_RETRIEVAL.md) §10、§13 中“RAG 由其他人实现”；[ACCEPTANCE_M1](ACCEPTANCE_M1.md) 中与本文冲突的目标档、加分档条目和第 2–4 周排期。[CALCULATION_PLANS](CALCULATION_PLANS.md) 继续有效：模型写计划、程序校验、不合格时用程序拼链，都按原设计。

## 0. 决策（用户 2026-09-25）

1. 设计上减少确定性部分的比重：各环节原来由规则做的判断交给模型，规则改为核对。
2. 在原框架上改：保留命令、确认、调度、状态保存和页面骨架。不写新的 Agent 循环与工具调用框架，不做确认前试算，流程图不重排、只改节点说明文字。
3. 保留规则路径：模型离线时，参数写全的请求照样能算；站点、设备、口语化理解等新能力需要模型。
4. 演示模型换成本机 8B–9B 级（任务 C8），上下文 ≥ 8K，仍只用本机模型。
5. RAG 由本项目实现：文档库、站点库与设备库、资料抽取。
6. 第 2 周六项按推荐：模拟数据由 Claude 编写、用户审核（附录 A）；原文没提到的量取卡片假设值，随确认一起确认（馈线损耗每端 2 dB、其他损耗 0 dB、预留 0 dB）；“要留 X dB 余量”作为要求值比较，不预先扣除；反求只做最小发射功率；距离只由坐标算；反求结果超过电台额定值时加一句提示。
7. 内容已明确、可照做的修改交给 GPT（Codex 任务单）；Claude 负责设计、提示词与模型行为调校，并审核结果。

## 1. 现状

原文参数全部由规则 `extract_request` 抽取，模型只从候选里选目标与条件；追问的回答也由规则解析；计算链由程序拼接；计算角色被 schema 锁成只能复述唯一许可的调用；审查角色只能在四个固定结论里选，降级时默认通过；最终结论是程序模板。关掉模型，结果几乎不变。

## 2. 各环节的改动

| 环节 | 现在 | 改为 | 规则的作用 |
| --- | --- | --- | --- |
| 理解需求 | 规则抽参数，模型只选目标与条件 | 扩展原有的需求模型调用：程序找出原文里每个“数字加单位”并编号，模型标出每个数是哪个参数或余量要求；站点、设备、反求意图（如“发射功率至少多大”）、目标与条件也由模型识别，每项附原文摘录 | 核对摘录逐字出现在原文；规则已标注的数与模型标注不一致时列为冲突，提问；站点、设备、反求问句找不到时只丢这一项 |
| 查站点、设备 | 没有 | 程序按模型认出的名称查 FactService（C10），取坐标、天线高度、设备参数作为参数来源 | 同名、缺项（如天线高度）、与原文不一致时，用原有提问面板问用户 |
| 写计划 | 程序拼链 | 专业计算 Agent 写计划：选公式卡与顺序，每步一句理由（见 §2a） | 程序校验（CALCULATION_PLANS §4 加 H3）；不合格重写一次，仍不合格用程序拼链，并在计划上写明原因 |
| 专业计算 Agent | 确认后照抄唯一调用 | 与写计划同一次调用：适用性评估（对题、自由空间是否适用、假设是否合理），只作提示；确认后不再调用模型（见 §2a） | 评估文字过 H4、引用须指向本任务事实；确认后的计算由程序执行（含视距拦截与反求复核） |
| 审查 | 四个固定结论选一 | 写审查意见（风险、假设的影响、调整建议）与结论（通过 / 请核对 / 超出适用范围） | 结论要引用已有事实；意见里的数字过 H4 |
| 解释 | 程序模板 | 写最终答复和逐步说明，引用依据 | H4；不通过时只显示逐步数值 |
| 补充、回答追问 | 规则解析（补充是否合并已由模型判断） | 补充由模型标注每个数改的参数并判断是否明确采用；回答追问仍是逐项填值，由规则解析 | 含不确定说法、否定或区间中的数、对不上参数的数或分句、与规则标注不一致时，挂为待澄清 |
| 调度、确认、状态、页面骨架 | — | 不变 | — |

## 2a. 专业计算 Agent：写计划与适用性评估（用户 2026-09-26 确认）

用户定：一次模型调用同时写计划与适用性评估；参数补齐、准备确认时才调用；评估只作提示，不挡确认；每步一句理由；评估看三件事（对题、自由空间是否适用、假设是否合理），至少一条；在计划卡顶部展开；站点记录加“环境”。展示细节交 Claude 定。计划与评估出自同一个 Agent，定位是计算书作者写明的适用条件；独立核对由程序校验承担，结果出来后再由审查角色复核。

- **时机**：需求整理完、没有待追问项、状态将为“待确认”时调用；追问阶段不调用，计划卡显示程序拼链的预览。回答追问、补充、改假设值后重新整理，同样只在可确认时调用。
- **输入**（只给本任务事实）：原文；目标、余量要求、反求；两端站点（名称、环境、模拟）与电台；每个参数的值、单位与来源（原文 / 手填 / 站点库 / 设备库 / 假设）；已确认条件；已审核公式卡（id、名称、输入、输出、适用条件、出处）。不给程序拼的链，免得照抄。
- **输出**（严格 JSON）：`steps` 为按顺序的 `{card, why}`，`why` ≤ 20 字，写这一步在链中的作用；`assessment` 为 `verdict`（`ready` 可以确认 / `review` 建议核对）与 1–3 条 `notes`（`kind`：`goal` 对题、`applicability` 适用性、`assumption` 假设；`text` ≤ 60 字；`refs` 指向本任务事实），第一条固定为 `goal`，说明计划怎样回答了问题。模型不写输入绑定，不写数值结果；输入由程序按参数来源绑定。
- **程序校验**：卡片存在且已审核；每张卡的每个输入恰有一个来源（已知参数或前面某步的输出），不能既是已知参数又由某步算出；最后一步输出目标量；没有用不到的步骤；步数 ≤ 8；距离由坐标得出时含视距一步，视距检查在路径损耗之前；输入来源与程序整理的一致（H3）。`why` 与评估文字过 H4（数字只能引用本任务输入）。
- **不通过**：带失败码重写一次；仍不通过用程序拼链，计划上写“程序拼链（模型计划未通过校验：原因）”。评估只保留引用有效且过 H4 的条目；一条不剩时写“未做模型适用性评估”。计划记 `origin`（`model` / `program`）与是否和程序拼链相同（一致率，加分项）。
- **模型不可用或确定性模式**：程序拼链，标“未做模型适用性评估”。
- **确认后**：不再调用模型（去掉“照抄唯一调用”），计算由程序执行。审查角色拿到计划阶段的评估，不重复同样的适用性意见，只评结果。
- **核对重放**：报告存模型输出；`check_report` 按存下的输出重放校验与 H4，改动会被拦下。
- **耗时**：写计划与评估一次调用目标 ≤ 18 s（9B）；准备确认的一轮约 20–28 s（原来 6–10 s）。
- **页面**：计划卡按计算书顺序排——标题（计划来源与校验）、目标与条件、适用性评估、步骤（出处与理由）、本次假设。细则见 [WORKBENCH_UI](WORKBENCH_UI.md) “计划卡”。
- **实现（2026-09-26，Codex 实现，Claude 调提示词）**：
  - 模型每类评估各写一条：对题、适用性必写；有假设值或电台时才写假设。由 schema 保证，存储仍为按对题、适用性、假设排列的 `notes`。
  - 数字核对以模型看到的本任务事实为准，包括输入、站点与电台记录、要求，与审查角色一致。
  - 写满字数上限的文字视为被截断，退回重写。
  - 真实 9B：9 个案例全部一次通过，与程序拼链一致，每次 9–15 s。见[调校记录](../codex/evidence/2026-09-26-plan-prompt-9b.md)。

## 3. 硬规则

| # | 规则 | 不通过时 |
| --- | --- | --- |
| H1 | 只用已审核（verified）的公式卡 | 计划不通过校验 |
| H2 | 单位与取值范围：按卡片单位换算，检查 min/max 与卡片声明的适用条件（由坐标得出的距离必须在视距内） | 计划不通过；正式计算中违反则停止，不给该步及后续数值 |
| H3 | 每个输入有来源：原文或用户回答（摘录必须逐字出现在该文本里）、站点库或设备库（记录必须存在）、卡片假设值、上一步。同一个量的不同来源数值不一致时，必须由用户裁决 | 列为冲突，提问 |
| H4 | 模型写的文字（答复、说明、审查意见）里的数字，必须来自本任务的计算结果或已确认输入，按显示精度比对 | 重写一次；仍不符则隐藏该段文字，只显示逐步数值，并注明“说明未通过数字核对” |

确认后才出正式结果、输入变更使旧确认与结果失效，这两条原有原则不变。

## 4. 参数与计划的扩展

- 参数来源 `origins.kind` 增加 `site`、`device`、`default`；模型标注的参数仍记为原文来源，位置就是那个数本身。数值与单位始终由程序从原文读出（允许“10个dB”这类量词），模型不输出数字，所以不设“模型换算”；中文数字（如“两千兆赫”）暂不支持，按缺项追问。
- 报告新增 `requirement`（余量下限）、`solve`（反求的未知量与问句位置）、`entities`（站点、设备的原文提及）；核对时按记录的模型输出重放，逐项复核它们仍落在原文上（2026-09-25 已实现，见 [A1 记录](../codex/evidence/2026-09-25-A1-labels.md)）。
- 计划目标增加 `requirement`（量、比较、阈值、摘录）与 `solve_if_unmet`（未知量，如 `tx_power_dbm`）；步骤可以用 `slant_range_wgs84`、`radio_horizon`；距离由坐标得出时，计划必须含视距检查。
- 反求在正式计算中执行，用 C11 的 `solve`，复核结果写进报告。
- 以上与参数来源的三种新 kind 于 2026-09-25 实现（计划另带 `checks` 与 `assumed`：本任务自己的假设），视距外的任务标为“需要其他模型”；见 [A2/A3 记录](../codex/evidence/2026-09-25-A2-A3-review.md)。

## 5. 模型调用

- 沿用 `role_model.suggest` 与 `response_format: json_schema`，每个角色仍是“最多两次结构化尝试，失败降级”。
- 降级：理解需求 → 规则抽参（只支持参数写全的请求）；写计划与适用性评估 → 程序拼链，在计划上注明“未做模型适用性评估”；审查 → 沿用现有做法，以程序校验结论发布并标“调用已降级”；解释 → 只显示逐步数值。
- 需求角色的 `max_tokens` 按新 schema 调整；换 9B、上下文 16K 后再按实测调整一条命令的时长上限（现为 90 s）。

## 6. 知识与 RAG

- 公式库：新增 `slant_range_wgs84`（WGS84 经纬高 → 地心坐标 → 两天线间弦长）与 `radio_horizon`（d = 4.12(√h₁ + √h₂) km，k = 4/3）。前者写成一条表达式会超过表达式语言 128 个语法节点的上限，按 CALCULATION_PLANS §8 做成登记的程序工具卡，附独立复算与公开算例。卡片参数新增 `default`，见决策 6。
- 站点库、设备库：`knowledge/facts/sites.json`、`devices.json`，全部 `simulated: true`，来源指向模拟站址表与模拟设备手册；数据见附录 A。
- 文档库：公开 ITU-R 建议书（P.525、P.530、P.453）与模拟文档，按页或章节切块，带定位，词项加向量混合检索；审查与解释引用它。ITU 原文只放在本机被忽略的目录，不进 Git 和源码包，仓库只存清单与哈希。英文原文配中文查询，所以词项检索加中英术语扩展，向量模型用中英文通用的 Qwen3-Embedding-0.6B（llama.cpp，CPU），任务 C12。
