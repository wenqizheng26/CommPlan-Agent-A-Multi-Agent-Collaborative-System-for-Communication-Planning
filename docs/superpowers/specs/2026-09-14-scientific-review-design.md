## 2. 公式、常量与符号规范

### 2.1 FSPL 采用基本关系式计算

建议默认计算采用：

\[
\ell_{\mathrm{bf}}=\left(\frac{4\pi d}{\lambda}\right)^2,
\qquad \lambda=\frac{c}{f},
\qquad \frac{L_{\mathrm{bf}}}{\mathrm{dB}}=10\log_{10}\ell_{\mathrm{bf}}
=20\log_{10}\left(\frac{4\pi df}{c}\right).
\]

其中 ℓbf 为线性损耗比；Lbf 为 dB 损耗，二者不能使用同一个未说明的“FSPL”数值。计算统一使用 m、Hz、m/s，c=299792458 m/s 是 SI 定义的精确值；π 的浮点计算仍存在数值舍入。[ITU-R P.525-5 式(5)](https://www.itu.int/dms_pubrec/itu-r/rec/p/R-REC-P.525-5-202411-I!!PDF-E.pdf)、[NIST 光速](https://physics.nist.gov/cuu/Constants/Value/c.html)。

换用 GHz 和 km 后，由基本式推导的系数约为 92.44778322188337。92.45 是其两位小数近似；92.4 是现有 ITU 数值式的舍入形式，不能简单称为“错误公式”。公式卡分别保存基本计算式、单位化工程式和来源原式，说明等价换算及舍入误差；公开来源形式保留，不把用户表重新纳入运行库。

只改变 FSPL 算法，在 f=4.5 GHz、d=0.2 km 且其他参数不变时：

| 项目 | 当前 92.4 形式 | 基本式计算 |
| --- | --- | --- |
| 自由空间损耗 | 91.4848501888 dB | 91.5326334107 dB |
| 接收功率 | −51.4848501888 dBm | −51.5326334107 dBm |
| 门限仍明确输入为 −62 dBm 时的余量 | 10.5151498112 dB | 10.4673665893 dB |

上述差异是更换常量处理方式产生的预期变化，不以“必须和参考表一样”判定新版本对错。该表不是更换噪声定义后的联合结果。

必须升级公式版本，记录常量表版本与表达式哈希；旧 JSON 和旧基准结果保留原版本，不覆盖。再计算时显示使用了新版公式。

### 2.2 逐条公式审查

| 公式 | 应保留的科学含义 | 本次计划的修订 |
| --- | --- | --- |
| 自由空间损耗 | 理想自由空间、单程、各向同性参考；远场适用 | 基本式优先；负损耗和近场异常拦截；现实场地满足程度另列 |
| 最大多普勒 | 一阶低速近似；相对速率只给频移幅度上界 | 写为 \(\lvert\Delta f\rvert\lesssim fv/c\)，不能把一般速率当已知径向速度；保留 0.001c 为项目范围限制的说明 |
| 热噪声功率 | \(P_N=k_{\mathrm B}TB_n\)，经典、匹配可用功率 | 温度与噪声等效带宽说明；不把带宽、占用带宽或比特率混为一谈；标注经典假设及参考面 |
| 热噪声谱密度 | \(N_0=k_{\mathrm B}T\)，线性单位 W/Hz | 与 dBm/Hz 表示分开；统一单边谱约定；明确是否包含接收机噪声 |
| 接收门限 | \(P_{min}=N_{0,sys}R_b\gamma_{b,req}\) 的相应 dB 表示，再加尚未计入的实现损失 | 区分系统谱密度路线和标准 NF 路线，统一 Rb 与 Eb/N0 的编码/信息比特定义；不能仅凭“误码−6”推导 Eb/N0 |
| 接收功率 | 同一频率、链路与参考面的功率收支 | 发射机端口功率与 EIRP 二选一；馈线、路径、极化及附加损耗不得重复计入；不把增益自动限制为正数 |
| 链路余量 | \(M_0=P_r-P_{min}\)，扣除指定预留后 \(M=M_0-M_{reserve}\) | 区分原始余量和剩余余量；负值表示未满足当前预算门限，正值不等于现场可靠度已验证 |

多普勒来源为 [NASA/JPL 42-154 式(14)](https://ipnpr.jpl.nasa.gov/progress_report/42-154/154L.pdf)，引用中需说明由径向频移推导上界。热噪声关系参考 [NASA Radio JOVE](https://radiojove.gsfc.nasa.gov/radio_telescope/resources/tech_talk-1.php)，常量值采用 [NIST 的 kB 精确定义](https://www.nist.gov/si-redefinition/kelvin/kelvin-boltzmann-constant)。接收预算与余量核对 [TI SWRA479A](https://www.ti.com/lit/an/swra479a/swra479a.pdf)，不能把来源中的特定设备经验范围泛化为全系统默认值。

### 2.3 噪声参考温度的重点修订

常规 NF 以 T₀=290 K 定义；线性噪声因子 F=10^(NF/10)，等效输入噪声温度 Tₑ=(F−1)T₀。在同一参考面且源与接收机噪声不重复计入的简化模型中，系统噪声温度为 Tsys=Tₛ+Tₑ。因此不能无条件将任意 Tₛ 的 kTₛ 直接再乘按 290 K 定义的 F。[Analog Devices 噪声分析](https://www.analog.com/en/resources/technical-articles/system-noisefigure-analysis-for-modern-radio-receivers.html)。

计划支持两条明确路径：已知系统噪声谱密度时直接使用且不再加 NF；采用标准 NF 时明确 T₀ 定义和源温度。第一项先阻止未说明参考关系的组合，第二项再登记完整关系和独立样例。290 K 作为 NF 定义中的参考常量不等于自动假定用户场景温度为 290 K。

### 2.4 全篇书写约定

- 变量斜体，单位、函数名和说明性下标正体；采用 \(k_{\mathrm B}\)、\(B_n\)、\(P_{\mathrm r}\)、\(\mathrm{NF}\)，避免把线性噪声因子 F 与 dB 噪声系数混写。
- 对数自变量必须为无量纲量或明确单位下的数值，例如 \(10\log_{10}[P/(1\,\mathrm{mW})]\)。工程数值式显式写 f/GHz、d/km 等比值。[NIST SI 书写规范](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-7-rules-and-style-conventions-expressing-values)。
- 输出使用 4.5 GHz、30 km、−62 dBm；统一 GHz、MHz、kHz、Hz、K 的大小写。自由输入可容错，但涉及 m/M、bit/byte 的歧义必须澄清，不能统一小写后误换算。
- dB 是比值的对数表示，dBm 是相对于 1 mW 的功率电平，dBi 是天线增益参考约定；不能仅凭单位字符串相似而代入。
- “已核对来源”“数值样例通过”“当前适用性”“现场验证”分列；不使用单一“verified”向用户暗示全方位科学认证。

## 3. DP、SF 与数值报告规则

DP 是小数位数，SF 是有效数字位数。建议如下，但这是本项目显示约定，不是国际标准要求所有通信量使用固定 2 DP / 4 SF。

| 层次 | 规则 |
| --- | --- |
| 输入 | 保存原始字符串、单位、来源片段及规范值；4.500 的尾零不能只靠 JSON 浮点值保留；不从书写位数擅自推断测量不确定度 |
| 内部计算 | 当前 Python float 为双精度；中间量不主动做展示舍入。不能称其“无误差”或与 SymPy 任意精度等同。不为排版引入高精度依赖 |
| 常规显示 | dB、dBm、dBi、dBm/Hz 默认 2 DP；Hz、W、距离等线性输出默认 4 SF；附“显示位数，不代表测量不确定度”说明 |
| 科学计数 | 极小或极大线性量采用科学计数或合适 SI 前缀；非零数不得默默显示为 0。对数小量可显示“接近 0，展开查看原值”，阈值结论仍用未舍入值 |
| 临界判定 | 负零只在显示层规范；−0.004 dB 的负余量不能因为显示 0.00 而被判为通过；提示接近门限及原值 |
| 已有不确定度 | 结果位数与评定的不确定度对齐；不确定度通常至多两位有效数字，必要时保留额外位；未知不确定度明确为未评定，不编造 ± 数值 |
| JSON | 同时保存 raw_value、display_value、format_policy、单位及版本；计算与比较只用 raw_value；原始输入文本独立存储 |

不确定度报告规则依据 [JCGM 100:2008 §7.2.6](https://www.bipm.org/documents/20126/2071204/JCGM_100_2008_E.pdf)。这不等于本期实现完整不确定度传播器；对“200±10 m”先保留范围并说明当前仅支持明确选定的标称值，不自动把它当 200 m 的精确输入。

## 4. 负数不能统一当成选错公式

| 负数出现在什么量 | 含义及页面行为 |
| --- | --- |
| 接收功率、噪声功率或门限，dBm | 相对于 1 mW 小于零，线性功率仍为正；正常显示并解释参考量 |
| 链路余量，dB | 当前接收电平不足以满足门限及预留要求；显示“计算完成／余量不足”，不用绿色成功样式代替通信判定 |
| 频率/距离数值式中的单独对数项 | 相对于所选单位小于 1 时可以为负；这些拆项不是独立的物理损耗，不叫“频率损耗”“距离损耗” |
| 本系统的无源馈线损耗输入 | 与正值损耗约定冲突，要求区分损耗和增益；不直接翻转符号 |
| 当前自由空间基本损耗 | 负值是超出该远场表达式适用范围的明显信号；拦截正式结果，显示原因，不取绝对值或截为零 |
| 实际有符号多普勒频移 | 正负与约定运动方向有关；目前登记的是非负幅度上界，不能替代实际频移 |

自由空间式在 d<λ/(4π) 时会算出负 dB；这是必要的异常检查，不是“d≥λ/(4π) 就一定满足远场”。远场还依赖源/天线尺寸和波长；尺寸未知时应报告“未完成远场核验”，不得自动认证实际场景。依据 ITU-R P.525-5 附录的距离适用说明及基本式作此检查。

## 5. 自然语言 → 自动填表 → 计算的交互设计

推荐方案为两阶段流程。保留直接填表入口，熟悉参数的用户无需先写自然语言。

| 备选 | 权衡 |
| --- | --- |
| 两阶段解析与核对（推荐） | 先展示解析证据、模型建议及缺项；计算快照可复核，最符合本项目当前可靠性目标 |
| 解析后直接计算 | 点击少，但用户只能在得到结果后发现目标或参数误解 |
| 完全固定表单 | 输入确定，但不利于用户自由表达和未来公式扩展 |

流程：输入或粘贴 → 点击“解析并填表” → 审阅已知环境、待求量、候选模型、参数 → 修改/补充 → 点击“确认并计算” → 查看结果和适用范围。

将“修正识别”“补充参数”“公式选择”合为一个常显的核对区，不再让用户寻找三个分散的折叠控件。字段数值、单位分列；原文依据、来源状态和问题提示就近显示。只展示所选计算链需要的字段，公式全集仍单独折叠。

以用户例题为例，解析后的表单应为：

| 栏目 | 自动填入 | 来源／状态 |
| --- | --- | --- |
| 环境 | 岸站 → 海上平台 | 原文可定位；不等于自由空间 |
| 待求量 | 传输损耗 | 原文明确 |
| 载波频率 | 4.5，单位 GHz | 原文“频率4.5GHz” |
| 路径距离 | 30，单位 km | 原文“距离30公里” |
| 计算范围 | 尚未确认 | “只看自由空间基准”或“估计实际场景”；不能默认前者 |
| 模型 | 自由空间基本损耗为可用基准候选 | 当前缺乏已登记的实际海上传播模型，不自动选用候选 |

就近提示：“已识别频率和距离。当前传播库只有自由空间基准，尚不能据此估计实际海面反射等影响。若只需理想基准，请明确选择；若需实际海上传播，本版本尚缺适用模型。”不要先要求一串天线高度、海况等参数，却在填完之后仍无可用模型。

用户明确选择基准后，新 FSPL 基本式在 4.5 GHz、30 km 下预计显示约 135.05 dB；该值只作为未来验收基准，本轮页面未执行这条新流程。选择实际传播时显示“当前模型库未覆盖”，不输出伪装为实际预测的自由空间值。

数据约束：解析接口不返回计算结果；计算接口以确认后的结构化草稿快照为输入，再做单位、范围、模型与版本核验，不重新调用 LLM 解释同一题。模型只能提出带原文证据的候选值/标签；进入计算的数字必须能由程序验证，歧义留空或列冲突。

修改原文使草稿过期；修改参数使上次结果过期；换题默认重置前题覆盖值。多目标用列表而不是单选框；模型候选、用户选择、缺失条件分别存储。新条件选项必须代表有定义的模型或计算范围，不能用模糊“其他传播”充当已实现的通用模型。

## 6. 分项实施顺序

每次只推进一个项目，完成其独立验收再进入下一项。项目范围、文件职责和完成标准统一见[工程需求基线第 9 节](../../requirements.md)，不再保留另一套相互冲突的阶段编号。

科学问题先对应 P1 适用性与状态、P2 七公式与单位、P3 数值显示；再进入 P4 自动填表与确认、P5 LangGraph 多 Agent、P6 候选比较和 P7 页面整合与分层验收。程序计算和硬规则检查不交给模型，单模型与多角色使用同条件对照。

新增两径、散射、雨衰等传播模型仍为独立后续范围，先核对公开来源、参数、频率/距离/统计适用范围和数据需求，再单项登记。不能仅凭关键词扩展本期科学能力。

## 7. 验收和费用约束

优先用已保存 JSON 检查问题原文、参数提取、候选公式、条件、版本、数值和缺项。无模型单元/接口检查用于可重复定位；不要为了生成“通过截图”反复操作页面或调用真实模型。浏览器目前只允许排版规划与核对，不模拟实际输入流程。

新测试至少覆盖：同一量的不同单位、0/负/极小/极大值、FSPL 近场、负余量临界值、噪声参考重复计入、题目修改后草稿过期、旧手动参数残留、多目标中独立可算项、未实现模型。独立期望值来自手算/基本关系，不从被测函数自身生成。

现有 `evaluate.py` 对数值案例一般只核对一个指定结果；完整预算案例主要核对余量，不能据此认为每个中间输出均已独立正确。新版本必须检查所有待求结果、输入参数和选择依据。检索相关性、参数准确性、模型适用性、数值正确性、页面操作可用性分别报告。

不把源码规则输出改名为真实 RAG 验收；不把历史 `passed=true` 视为用户体验无问题。旧报告保留为特定版本和特定断言的历史证据。
