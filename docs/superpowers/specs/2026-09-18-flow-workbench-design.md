## 八模块

1. 任务与自然语言输入：原文、补充参数、目标条件、版本和恢复。
2. 运行画布：执行流程默认，总体架构可切换；当前节点、连线和分支可点击。
3. 参数对应：中文名、符号、原始值/单位、规范值/单位、来源、状态；原文定位和公式变量绑定。
4. 模型与计划：登记模型、依据、适用条件、假设、步骤和预期输出。
5. 公式与代入：数学排版、变量定义、单位、已确认实际代入和登记版本。未确认只显示草稿，不能显示正式结果。
6. 来源证据：区分原文来源、公式来源、模型选择依据；展示库内片段、定位、版本、链接与审核限制。缺少定位明确标注，不编造原文摘录。
7. 校验与结果：硬校验、结果意义、限制、引用和 JSON 导出。完整 LLM 解释未接入时明确说明。
8. 执行记录：真实开始/结束事件、耗时、分支、异常、历史版本与恢复。

## 布局和联动

顶部任务/版本/状态；左侧需求；中央 SVG 流程画布；右侧上下文详情（概览、参数、计划、公式、依据、结果）。详情可展开为宽面板；底部可折叠事件时间线与历史记录。小屏转单列，画布可横向滚动，键盘可选节点。减少动画偏好下禁用流动与脉冲。

选参数定位原文高亮，并能定位公式变量；公式链接定位证据卡；结果回链公式和参数。点击节点自动选择最相关详情页，选择证据保留当前任务。历史查看具有显著只读提示，所有命令只作用当前版本。返回当前版本明确。

## 运行状态与数据边界

真实事件由后端写入独立 activity SQLite，主任务/快照/checkpoint 的同事务提交逻辑不改变。事件包括 task_id、event_id、run_id、revision、seq、node、phase、at、details。单次 HTTP POST 仍同步执行，另用 GET activity 轮询，慢调用期间可观察已开始节点；不添加假计时流程。

事件为运行观察，不是正式任务状态。正式提交成功后追加 committed；异常回滚追加 rejected；服务重启后未结束的记录标 interrupted，不把中断记成业务成功。重复事件重放只记录 replayed，不能伪造节点重跑。副记录失败不能影响业务结果。UI 标明正在运行的结果尚未保存；仅 committed 的主状态可确认/发布。

灰色未开始、蓝色运行、绿色完成、橙色等待输入/确认、红色失败；未接入独立样式。架构图沿用任务流/能力调用/状态三类线，不把所有连线当作顺序执行。当前流程的解析由程序完成，LLM 意图建议可跳过，缺项/冲突进入补问，依据/模型缺口停止。取消、重启和过期响应不得显示为成功。
