## 实现

- 底层继续使用 `AWAITING_INPUT`，任务增加 `input_issues`、`resolved_input_issues`、`waiting_reason`。页面展示需求待澄清、待补参、待消解冲突和模型能力不足，避免每个 Agent 各自提出一组重复问题。
- 问题标识由类型、字段和来源生成，按字段/问题去重。目标不明确时先问目标；模型支持范围确认后才进入参数核对。结构化问题支持部分回答，未答内容保留。复杂开放语义通过直接编辑任务处理，当前不是任意领域的自主需求访谈。
- 新 `answer` 命令校验任务/状态版本和问题标识，回答保留原话及选择标签；每次回答形成新 revision，使旧确认与结果失效。SQLite 任务、历史、幂等回执与 checkpoint 沿用同一事务。activity 也使用新 revision，仅提供观察信息。
- 支持频率与距离的明确上下界、± / +- / +/- 容差和离散候选；所有数值、端点与单位由确定性程序解析。无边界近似表达、否定/条件表达、来源冲突、零或负端点继续阻断。
- 区间为正值自由空间损耗的单调端点计算；离散候选分别报告，可与区间组合。单参数最多 8 个候选，一次工具执行最多 64 组端点/候选组合；不解释为概率区间，不推断输入相关性。模型建议仍不能生成数值或覆盖工具结果。
- 区间结果同样经过 8 项硬校验及结构化审查，独立数量级检查使用 `4πdf/c`。登记公式与常数未修改。2±0.1 GHz、1 km 的输出为 97.975072–98.844386 dB。
- 页面顶部集中展示问题、问题数量和已知信息；图中新增“需求确认与补充”与返回分支。历史回答、模型模式及数值范围可追溯。
