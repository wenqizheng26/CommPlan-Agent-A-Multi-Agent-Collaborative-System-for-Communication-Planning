## 改动

- **提示词改为中文**，分两部分写清：
  - 写计划的规则：
    - 每个输入要么已在输入里，要么由前面一步算出。
    - 由坐标算距离后，紧接着算视距。
    - 反求不是步骤。
    - 每步理由不超过 16 字，不写数字。
  - 三类评估各写什么：
    - 对题：只写事实里有的要求与反求。
    - 适用性：按两端环境判断路径（有一端是海岛为跨海面，有一端是内陆以陆地为主），说明自由空间结果偏乐观的原因。
    - 假设：点名可核对的假设值（如馈线损耗）。输入超出电台额定值或频段时，优先写这一点。
  - 结论通常为“可以确认”。只有计划没回答原文，或输入与记录不一致时，才写“建议核对”。
- **模型的输入改写**：只给本任务事实，每项带引用编号，包括：
  - 原文、目标、要求、反求、条件；
  - 两端站点（哪一端、环境、是否模拟）；
  - 电台（额定功率、增益、灵敏度、频段）；
  - 每个输入的值和一句话来源，如“原文“2 GHz””“站点库 A站”“假设（卡片默认值）”；
  - 本次假设；
  - 公式卡。

  程序拼的链不给模型。A→B 的输入从 8.6k 字符减到 4.5k，提示 token 从 3627 降到约 2500。
- **评估每类一条，由 schema 保证**：对题、适用性必写；只有存在假设值或电台时，才提供“假设”这一项。存储格式不变（`notes` 按对题、适用性、假设排列），页面不用改。
- **数字核对（H4）**：以模型看到的事实为准，与审查角色一致，所以“高于 XX-100 额定 37 dBm”能通过。核对重放按同样方式重建事实。评估可以引用站点、电台记录；重复的引用只保留一次。
- **截断**：理由写满 20 字、评估写满 60 字，视为被截断，退回重写。计划失败码附中文说明，重写时给模型看。
- **重写把计划改坏时**：如果第一次的计划已经通过、只是评估没过，而重写把计划改坏了，就保留第一次的计划，只隐藏没通过的评估条目。原来的做法是退回程序拼链。
- **审查角色**：
  - 只拿到评估里的几句原文。
  - 写意见那一段开头要求：只写由这次结果得出的新判断，确认前已看过的提示不再写。
