# M1 A1：模型标注数量、要求、反求与站点设备（2026-09-25）

工作区 `CommPlan-Agent-M1`，分支 `claude/calc-plans`，起点 `913da15`。设计见 [AGENT_LED](../../design/AGENT_LED.md) §2、§4。

## 改动

- 程序找出原文里每个“数字加单位”并编号（`planning/services/requirement_quantities.py`）；否定、假设、区间、候选值里的数不交给模型。
- 需求模型调用（`formula_rag/model.py`）的输出增加 `quantities`、`solve`、`sites`、`devices`。模型只标出每个数的含义，数值与单位始终从原文读出。
- 合并（`collect_parameters`）：规则没标注的数采用模型标注；规则已标注而模型标得不同，记 `LABEL_CONFLICT` 并在提问面板列为冲突；余量下限（如“余量至少10dB”）经模型标为要求后，不再被规则当作无法解析的数值。
- 报告新增 `requirement`、`solve`、`entities`。`check_report` 按 `MODEL_CALL` 中记录的标注重放，并逐项复核标注仍落在原文上；篡改标注、数值或摘要都会被拦下。
- 规则核对放宽两处：“能通吗”“够不够”“能否满足”等可行性问法可以由模型对应到链路余量；“能不能通”这类正反问不再当作否定。

## 真实模型实测中发现并修正

| # | 现象 | 修正 |
| --- | --- | --- |
| 1 | “能不能通”被当作否定句，目标被拒 | 否定检查前先去掉“X不X”形式的正反问 |
| 2 | 模型给设备引了错误的分句，整份理解作废 | 站点、设备、反求问句找不到时只丢这一项，记 `MODEL_LABEL_DROPPED`；名称先在所引分句里找，再在全文找 |
| 3 | “10个dB”没被认作数量 | 数字与单位之间允许量词“个” |
| 4 | 模型把“预留余量10dB”标成余量要求，规则标的是预留余量，没有报冲突 | 余量要求落在规则已标注的数上时，同样记 `LABEL_CONFLICT` |
| 5 | 反求问句被拆成两段（“如果不能，发射功率至少多大”），模型只引了条件句 | 在所引的那句话里找含“发射功率”的分句作为位置 |
| 6 | “够用吗”“能否满足”不在可行性问法清单里 | 补入清单；站名写成“A站”而原文是“A到B两个站”时，去掉“站”字再找 |
