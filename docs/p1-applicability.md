# P1：适用范围与结果解释

2026-09-15，程序规则版本 `p1-1.0.0`。本项修复适用性和结果解释，尚未接入 LangGraph 或多 Agent。

## 行为

| 情形 | 当前行为 |
| --- | --- |
| 岸站到海上平台、4.5 GHz、30 km，只问传输损耗 | 保留参数，说明实际环境模型尚未覆盖，请用户明确是否计算自由空间基准 |
| 选择自由空间，距离不大于 λ/(4π) | `free_space_nearfield`，不发布有效损耗，下游计算暂缓 |
| 自由空间筛查通过 | 仍明确未完整验证天线远场条件；不宣称真实传播模型有效 |
| 负 dBm | 正常功率电平，参考为 1 mW |
| 余量为负／零／正 | 分别输出 `below_threshold`／`at_threshold`／`above_threshold`；扣除预留量后的预算判断不等同于现场可靠性结论 |
| 未确认噪声参考 | `noise_reference_unconfirmed`；接收门限不给数值，独立噪声功率等仍可计算 |
| 标准确认与温度/谱密度矛盾 | `noise_reference_mismatch`，不直接套用 NF 相加路线 |

λ/(4π) 只是由自由空间关系得到的明显异常筛查边界，不是完整远场判据。实际远场适用性还与天线尺寸、波长、距离和环境有关。现有 92.4 舍入式在该边界附近仍可能产生略负的算术值，本项也阻断此类正式输出；不截断成零、不改公式常量。基本式与版本化计算由 P2 处理。

## 噪声确认

本项暂时只支持标准路线：匹配源在接收机输入端的温度为 290 K，输入谱密度仅含该源噪声，NF 按 T0=290 K 定义，接收机噪声尚未重复计入。当前表单升级前，可在原问题中另起一行：

```text
确认采用标准290K噪声路线
```

此文字表示对上述定义的明确确认。仍须输入温度 290 K 或相应谱密度。单独出现 290 K 或 −174 dBm/Hz 不构成确认，否定、引用、疑问或假设中的确认文字也不放行。模型不能确认这个字段。接口对应：

```json
{
  "text": "原问题与显式参数",
  "noise_reference": {"mode": "standard_290k", "confirmed": true}
}
```

结构化输入优先于文本；`confirmed` 必须为布尔值。它只确认含义，不自动补数值。明确输入 −174 dBm/Hz 时按工程舍入值使用，并披露与精确 k×290 K 的差异；程序不改写用户输入。非 290 K 源温度和已包含接收机噪声的系统总噪声需要不同路线，本项先阻断，P2 再审核与实现。当前路线的一致性容差为 1e−8 dB，仅用于浮点比较，不代表测量精度或物理不确定度。

NF 的标准参考温度关系依据 [Analog Devices 的系统噪声系数分析](https://www.analog.com/en/resources/technical-articles/system-noisefigure-analysis-for-modern-radio-receivers.html)；自由空间关系依据 [ITU-R P.525](https://www.itu.int/rec/R-REC-P.525/en)。程序中的异常筛查和发布边界是本项目保守实施规则，不是标准给出的充分适用性认证。
